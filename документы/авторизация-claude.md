# Авторизация Claude на сервере

Единственный шаг установки Агента, который нельзя выполнить программно.

## Почему нельзя автоматизировать

Интерфейс Claude Code принимает только живое нажатие клавиши. Проверено четырьмя способами — ни один не сработал:

| Подход | Что произошло |
|---|---|
| `expect` с потоком вывода через SSH | канал рвётся от управляющих символов интерфейса |
| `expect` с логом в файл и распознаванием текста меню | текст разбит escape-последовательностями, регулярные выражения не срабатывают |
| `expect` со слепыми нажатиями Enter | мастер проходит, ссылка ловится, но код в поле ввода не отправляется |
| Запись `\r` напрямую в мастер-псевдотерминал (`/proc/PID/fd/N`) | игнорируется |

**Работает `tmux`.** Он создаёт на сервере настоящий терминал, и `tmux send-keys` доставляет нажатия так же, как живые пальцы. Сработало с первой попытки.

**Вывод на будущее: любой интерактивный текстовый интерфейс на сервере автоматизируется через tmux, а не через expect.**

## Как это сделать

Подключитесь к серверу и выполните по очереди.

### Шаг 1. Запустить Claude в настоящем терминале

```bash
sudo -u agent -H tmux new-session -d -s login -x 200 -y 50 claude
sleep 12
```

### Шаг 2. Пройти мастер первого запуска

Два экрана — тема оформления и способ входа. Значения по умолчанию верные, просто подтверждаем.

```bash
sudo -u agent -H tmux send-keys -t login Enter
sleep 6
sudo -u agent -H tmux send-keys -t login Enter
sleep 6
```

> Если появится вопрос про доверие папке — ещё одно нажатие Enter.

### Шаг 3. Забрать ссылку

```bash
sudo -u agent -H tmux capture-pane -t login -p | tail -20
```

На экране появится ссылка вида `https://claude.com/cai/oauth/authorize?...`. Она длинная и переносится на несколько строк — собрать её в одну можно так:

```bash
sudo -u agent -H tmux capture-pane -t login -p \
  | sed 's/[[:space:]]*$//' \
  | awk '/^https:\/\/claude\.com/{f=1} f{printf "%s", $0} f&&/state=/{exit}'
```

### Шаг 4. Авторизоваться в браузере

Откройте ссылку, войдите под аккаунтом с подпиской **Pro или Max**, нажмите **Authorize**. Страница покажет код.

> Не выбирайте «API key» и не запускайте `claude setup-token` — это другие способы входа, для бота они не подойдут.

### Шаг 5. Вернуть код

```bash
sudo -u agent -H tmux send-keys -t login -l "ВСТАВЬТЕ_СЮДА_КОД"
sudo -u agent -H tmux send-keys -t login Enter
sleep 15
sudo -u agent -H tmux capture-pane -t login -p | tail -5
```

Должно появиться `Logged in as ...` и `Login successful`.

### Шаг 6. Закрыть и запустить бота

```bash
sudo -u agent -H tmux send-keys -t login Enter
sleep 5
sudo -u agent -H tmux kill-server
systemctl start agent-bot
systemctl status agent-bot --no-pager
```

Проверить, что Claude действительно отвечает, а не просто авторизован:

```bash
sudo -u agent -H bash -c "cd /home/agent/workspace && claude -p 'ответь одним словом: работает'"
```

## Если доступ слетел позже

Пропуск Claude живёт около суток и обновляется сам. Раз в год-два обновление может сломаться — после смены пароля в аккаунте или случайного запуска `claude setup-token`.

Признаки: бот перестал отвечать или отвечает мгновенно пустыми сообщениями.

Лечение — тот же порядок с самого начала. У бота для этого есть команда `/reauth`.
